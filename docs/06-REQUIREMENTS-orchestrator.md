# 서브프로젝트 ② 오케스트레이터 코어 — 요구사항 (초안 v0.1, 2026-11-05)

양식은 `00-TEMPLATE.md`(확정 / 가정 / 미결정 / 실험할 것)를 따른다. 상위 요구사항은 `01-REQUIREMENTS.md`(FR1~FR15), 진행 위치는 `전체_계획서.md`.

## 1. 목적
AI가 만든 변경을 **신뢰할 수 있는 환경에서 실행·검증**하고, 승인이 필요한 행위를 **사람 대신 실행하지 않고 대기**시키며, 자율 단계(L0~L3)를 증거로 관리하는 실행 계층. ① 검증 게이트가 판정하고, ②는 그 판정이 의미 있도록 **실행 환경과 작업 흐름을 통제**한다.

## 2. 확정 (사실·실측·사용자 결정)
| 항목 | 내용 | 근거 |
|---|---|---|
| 격리 실행 환경 | **홈서버 OpenStack의 Linux VM 두 개** (사용자 결정 2026-11-05): **에이전트 전용 VM**(Claude/Codex 실행, 코드 작성)과 **검사 전용 VM**(테스트·빌드 실행). 두 VM은 서로 직접 통신하지 않는다 | 질문 답변(사용자 제안) |
| 홈서버 자원 | 8코어, 메모리 전체 31GB(사용 가능 약 17GB), 디스크 `/` 여유 54GB(43% 사용), 실행 중 VM 2개(2026-11-05 측정). VM 2개 추가는 가능하나 디스크가 빠듯하다 | 홈서버 직접 확인 |
| 대소문자 구분 | Linux VM은 대소문자를 구분하는 파일 시스템 → macOS 접힘 문제(`Node_Modules` 그림자 등)의 근본 해결 | ① 재리뷰 6~8차 |
| 승인 필수 하한선 | 파일·데이터 삭제, 운영 서버·계정 권한 변경은 어떤 단계에서도 사람 승인 | FR5, 요구사항 C4 |
| 허용 목록 | 무인에서도 자동 허용: 작업 브랜치 commit/push, Draft PR, 블로그 비공개 초안, 본인 알림 | FR12 |
| 무인 승인 대기 | 승인 필요 행위는 실행하지 않고 대기 목록에 남김, 해당 하위 작업만 중단 | FR5 |
| 자율 단계 | L0~L3, 승격은 시스템이 제안하고 사람이 승인, 강등은 자동 | FR14 |
| 웹 화면 | 승인 대기·큐·판정·변경 보기 웹 화면 필요, 웹에서의 승인은 별도 보안 설계 후에만 | FR15 |
| 보안그룹 | 홈서버 OpenStack은 `firewall_driver=noop`라 **보안그룹이 적용되지 않음**(2026-11-02 확인). VM은 같은 LAN의 다른 장비에 닿을 수 있다 | 홈서버 확인 기록 |
| 게이트의 한계 | 테스트 코드가 환경 변수 전체와 `~/.aigate/` 쓰기 권한을 받음, 이력이 키 없는 해시 체인 | ① 최종 리뷰 I4, 설계서 4장 |

## 3. 요구사항 (제안, 확정 전)
| ID | 요구사항 | 상태 |
|---|---|---|
| OR1 | 검증 대상 코드(테스트·빌드)는 **검사 전용 VM**에서만 실행한다. 이 VM에는 사용자의 자격증명(구독 로그인, 저장소 쓰기 토큰, 승인 기록)을 두지 않는다 | 제안 |
| OR1a | **에이전트 전용 VM**에는 에이전트의 구독 로그인 정보만 둔다. 저장소 **쓰기** 토큰과 승인·이력 파일은 두지 않는다. 에이전트는 VM 안 저장소에서 **로컬 커밋**만 하고, 오케스트레이터가 그 커밋을 읽기 전용으로 가져간다(VM에서 push 없음) | 제안 |
| OR1b | 검사 VM은 **git 객체(커밋 트리)만** 받아 깨끗한 작업 트리를 만든다. 에이전트 VM의 작업 트리·미추적 파일·git 설정은 검사 VM에 가지 않는다(① 게이트의 `dirty_tree`, `skip-worktree`, `.git/info/exclude` 류 우회가 구조적으로 사라진다) | 제안 |
| OR2 | 두 VM 모두 **VM 안쪽 방화벽**(nftables 등)으로 네트워크를 제한한다: 기본 차단 + 허용 목록, LAN(Mac mini, gpu-server, 홈서버 관리망 등) 차단. 보안그룹은 믿지 않는다. 에이전트 VM의 허용 목록은 LLM API 도메인과 저장소 읽기 주소 정도, 검사 VM은 패키지 저장소 정도 | 제안 |
| OR3 | 검사 실행 환경에는 **허용한 환경 변수만** 전달한다(allowlist). `~/.aigate/`(승인·이력)는 VM 밖에 두고 VM에서 쓸 수 없다 | 제안 |
| OR4 | 작업마다 깨끗한 환경(스냅샷에서 복원하거나 새 VM/컨테이너)으로 시작하고, 작업이 끝나면 되돌린다 | 제안 |
| OR5 | 승인 대기 목록은 영속적이다(재부팅 후에도 남음). 항목: 작업, 이유, 승인 해시, 생성 시각 | 제안 |
| OR6 | 허용 목록은 설정 파일로 선언하고 변경은 사람 승인 대상이다 | 제안 |
| OR7 | 작업 상태는 상태 머신으로 관리한다: 대기 → 실행 중 → 검증 중 → 승인 대기 / 완료 / 실패 / 중단 | 제안 |
| OR8 | 게이트 판정과 증거 보고서는 VM 밖(오케스트레이터)이 받아 보관한다. VM 안에서 만든 보고서는 신뢰하지 않는다 | 제안 |
| OR9 | 자율 단계는 작업 종류별로 저장하고, 승격 제안은 이력(`stats`)에 근거한다. 하한선은 풀리지 않는다 | 제안 |

## 4. 가정 (확인 방법)
| 가정 | 확인 방법 |
|---|---|
| 홈서버 OpenStack에서 VM을 하나 더 만들어 상시 또는 필요 시 켤 수 있다 | 홈서버 자원(CPU·메모리·디스크) 확인, VM 1개 생성 시험 |
| VM 안 방화벽만으로 LAN 접근을 막을 수 있다(보안그룹이 없어도) | VM에서 Mac mini·gpu-server·관리망으로 접속 시도, 모두 차단되는지 확인 |
| VM 스냅샷·복원이 작업 단위로 쓸 만큼 빠르다 | 복원 시간 측정 |
| Go·Node·Python 툴체인과 의존성 내려받기가 허용 경로로 충분하다 | `sample-collector` 테스트를 VM에서 실행해 보기 |
| 에이전트를 VM 안에서 실행하려면 구독 로그인 정보가 에이전트 VM에 필요하다(프롬프트 주입으로 유출될 수 있으므로 외부 통신 허용 목록으로 제한) | 각 CLI의 헤드리스 로그인 방식 확인(미조사), 허용 목록으로 외부 유출 시도 차단되는지 시험 |
| 두 VM 합쳐 약 10GB 메모리·40GB 디스크면 충분하다 | 사양을 정해 생성한 뒤 `sample-collector` 테스트와 에이전트 작업을 돌려 보기 |

## 6. 실험할 것
- VM에서 `sample-collector`의 `go vet ./... && go test ./...`를 돌려 시간과 성공 여부 측정(macOS 대비)
- VM 안 방화벽 기본 차단 + 허용 목록 구성과 LAN 차단 검증
- VM 스냅샷 복원 시간
- `aigate run`을 검사 VM 안에서 실행하는 구성과 오케스트레이터가 원격 실행하는 구성 비교
- 에이전트 VM에서 Claude/Codex 헤드리스 로그인과 허용 목록만으로 동작하는지, 에이전트 커밋을 오케스트레이터가 읽기 전용으로 가져오는 경로(git over ssh, bundle) 비교
